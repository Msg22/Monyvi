## 3. Proposed future T038 presentational sheet APIs (not published exports)

**Both new sheets are shaped readonly view props and callbacks only.** No `@monyvi/db`, service/repository, canonical reducer, parser, SQL, actor lookup or financial writer imports in the **new T038 UI**. They do not copy currency/account domain enums: the facade supplies validated and localized display strings, eligible candidate IDs, scoped action callbacks, and explicit availability. Identity never comes from a nickname alone. All target/revision/owner checks run in T034/T036/T039.

**`AccountChoiceSheet.tsx`** (future T038): proposed props `{visible:boolean, title:string, contextSubtitle?:string, scopeDisclosure:string, candidateOptions:readonly {id:string, displayName:string, identityDetails:string, accessibilityLabel:string, isEligible:boolean}[], selectedCandidateId:string|null, canUseSelection:boolean, isBusy:boolean, onSelectCandidate:(id:string)=>void, onUseSelected:()=>void, onClose:()=>void}`. `selectedCandidateId` is **null at entry** even when one/three candidates are listed; none is implicitly first/default/previous account. Display 3 disambiguated QNB/EGP identities using owned provider, type, currency and masked card digits, fully accessible with 44dp option target and a selection state; `Use account` is disabled if selection null, ineligible or busy. Candidate press updates only **temporary controlled choice**; separate Use asks the facade to revalidate and dispatch for the bound initiating **row** or **group**. The local component does not decide the scope from account names or a fake ID. `scopeDisclosure` provided by facade distinguishes `For Lunch at Talabat` row scope from `Replace QNB for all 3 linked transactions` group scope. Closing cancels pending choice and restores initiating focus.

**`CurrencyConfirmationSheet.tsx`** (future T038): proposed props `{visible:boolean, contextSubtitle:string, candidateOptions:readonly {code:string, label:string, accessibilityLabel:string}[], selectedCandidateCode:string|null, canUseSelection:boolean, isBusy:boolean, onSelectCandidate:(code:string)=>void, onUseSelected:()=>void, onChooseAnother:()=>void, onClose:()=>void}`. The EGP/USD conflict begins with **null** selection; tapping a candidate sets only transient controlled selection; `Use` remains disabled until explicit valid choice, while Cancel/Back preserves unresolved currency. `Choose another currency` is a **mode transition in the parent facade**, closing the conflict sheet before showing **the existing** `CurrencyPicker` with `selectedCurrency={null}` and already-localized `contextSubtitle`. No duplicated currency modal/list, no stacked active sheets, no auto-accept on open. A picker currency-row tap directly chooses that code (the original picker callback), returns to the initiating review and re-runs T036 row-scoped eligibility; no independent extra “Use” inside the picker.

**The contract is UI only.** Keep `TransactionReviewProps`, `TransactionItem` existing checkbox/edit actions, `ReviewActionBar` Save, Voice Retry/transcript and SMS Review later intact until T054 owns canonical facade wiring; T038 cannot silently extend legacy Save or invent a review route. Group/row identity and exact applicable pending changes are bound externally, not embedded in view-only presentation classes.
