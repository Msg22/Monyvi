## Scope and interaction decisions proposed for approval

- Keep the existing shared PageHeader, underline mode tabs, standalone route, design tokens and responsive layout patterns.
- Dark allowance badge uses slate-700 with green microphone glyph, matching the examples heading badge. Light-mode badge retains its existing approved treatment.
- English example glyphs keep their existing identities: orange restaurant, blue car, gold coffee. Existing Arabic reference-specific example copy and icon presence remain unchanged; any visible example glyph uses its matching category color.
- Examples card gets a 44dp minimum close target; accessibility label: Dismiss examples / إخفاء الأمثلة. Dismissal removes the whole card immediately and persists per authenticated account on this device, across route changes, app restart, language/theme changes, and sign-out/sign-in. Other accounts keep their own preference. No hosted schema or sync change is proposed.
- Mic tap shows Starting immediately, before awaiting allowance refresh or recorder preparation. Listening and elapsed recording time begin only after native capture starts. Repeated taps cannot start duplicate captures.
- Suggested motion: two thin ripple strokes expanding from the mic boundary to the existing outer listening region over 1.4 seconds, staggered by 700ms; activity bars cycle gently over 1.2 seconds. This is a recording activity indicator, not a measured volume claim.
- Paused stops motion and freezes time; resume restarts activity. Reduced-motion mode shows static indicators. Unmount, discard, cancellation and account changes stop animation and recording work.
- Parsing uses a restrained 1.6-second waveform/dots/receipt loop, no percentage, staged completion claims or invented financial details. Reduced-motion mode uses a static illustration. Actual allowance/loading-fetch skeletons remain distinct from this processing activity state.
- Replace the record-introduction/permission modal with an inline permission explanation only when native permission is genuinely missing. Granted users start directly on mic tap. Refresh native permission when appropriate so a stale default false cannot show an unnecessary prompt.
- First-use AI processing consent remains required; this proposal does not remove its existing privacy consent sheet.
- Blocked microphone permission uses inline recovery and the existing Settings/Manual actions.
- Recording-error Try again enters Starting directly, with no visible idle detour. Retained-audio submission retries still resend the same request identity rather than start another recording or charge.
- Unavailable-state Try again is proposed to refresh allowance and continue into Starting automatically when eligible, instead of requiring a second mic tap. Daily-limit and burst-limit enforcement still apply.
- Recorder-start errors must surface recovery rather than leave a false Listening screen.

## Verified diagnosis at d45745a5c8a13db082eab24e12c2cc072e26c124

- add-transaction.tsx sets isVoiceStartPending, but voiceState does not render it.
- useVoiceTransactionFlow.startFlow waits for availability refresh before switching visible flow state.
- retryRecording sets idle before awaiting startFlow, permitting an idle flash.
- PermissionRecoveryModal is rendered for the pre-native microphone explanation, using generic recording-introduction copy.
- useVoiceRecorder initializes hasPermission=false and resolves the actual permission asynchronously.
- VoiceTransactionEntry's recording pulse exists but uses low-opacity treatment; parsing renders a circular Skeleton.
- ExamplesCard has no dismiss callback or durable hidden preference and uses slate-colored English example glyphs.
- useVoiceRecorder.start catches preparation failures without rethrowing; caller can retain recording flow state after failure.
